## 第二轮定点修正（4 个阻塞问题）

### 修正内容
1. **历史快照与系统成本联动（加载保护）**：
   - 新增 `_loading_record` 标志，`load_record_payload` 开始时置 True，`finally` 中置 False
   - `set_calculation_cost` 在 `_loading_record=True` 期间只缓存 `_live_cost`，不退出快照
   - 加载完成后用户修改系统成本 → 退出快照、覆盖成本、按当前 driver 重算、标记当前推算
   - 不依赖浮点成本相等判断，用明确保护状态
   - 异常时 `finally` 正确复位 `_loading_record`

2. **SHEIN 核价编辑行为**：
   - `_on_shein_quote_changed` 不再调用 `_exit_snapshot_mode` 和 `_refresh_all`
   - 只更新 `_shein_quote_usd`、`txt_shein_rmb`（RMB 换算）和差额提醒
   - 不改变 driver、不退出快照、不重算利润/规则
   - 即使保存后汇率/规则已变化，单独改核价也不间接改变利润

3. **旧记录保存逻辑**：
   - 新增 `_legacy_exited` 标志，`load_from_record` 置 False，`_exit_snapshot_mode` 置 True
   - `export_profit_scenarios` 检查 `_snapshot_legacy and not _legacy_exited` → 保持 `legacy_compatible=True`、活动场景为空
   - 只有 7 类明确操作（编辑利润率/无活动售价/无活动利润/活动后利润/活动预留/系统成本变化/主动重算）才退出 legacy
   - 退出后界面显示"当前推算"，可使用双场景 schema

4. **快照状态提示**：
   - 复用 `lblProfitConclusion` tooltip（不新增控件、不改冻结 .ui）
   - 三状态：`历史快照` / `旧记录兼容数据` / `当前推算（非历史快照）`
   - 无差额提醒文本时直接在 lblProfitConclusion 显示状态文案
   - 有差额提醒时保留提醒文本，状态写入 tooltip

## 第三轮定点修正（3 个阻塞问题）

### 修正内容
1. **payload 数据一致**：`build_record_payload` 在快照/legacy 状态下（`is_in_snapshot_mode()` 返回 True），`layers.calculated.exchange_rate`、`system_cost_rmb`、`layers.adopted.calculation_cost_rmb` 均使用 `profit_scenarios` 快照值，不混入 `self.settings` 当前汇率或 `self.current_system_cost`。当前模式继续用当前值。新增 `is_in_snapshot_mode()` 属性。
2. **旧记录原样保存**：`load_from_record` 保存 `_legacy_snapshot` 字典（原始 na 售价/利润 RMB/USD、利润率、成本、汇率、规则状态）。`export_profit_scenarios` 在 legacy 未退出时原样输出 `_legacy_snapshot` 值，不重新推导 `na_profit_rmb = na_price_rmb - cost`。故意不满足公式的旧记录利润保持原值。
3. **tooltip 去重**：`_update_snapshot_status_label` 写入前遍历 tooltip 行，删除已有 `[利润区状态]` 行，只追加一条最新状态。连续刷新不累积。状态切换后旧状态行被清除。
