## 3. 利润

### 3.1 双场景公式

```text
计算总成本 = 利润区当前采用的成本 RMB（上方系统成本变化时自动覆盖）

无活动场景：
  无活动售价 USD = SHEIN 店铺真实售价（用户输入）
  无活动售价 RMB = 无活动售价 USD × 汇率
  无活动利润 = 无活动售价 RMB + 本场景规则收入 − 计算总成本 − 本场景规则成本

活动场景：
  活动后售价 USD = 无活动售价 USD ×（1 − 活动预留%）
  活动后售价 RMB = 活动后售价 USD × 汇率
  活动后利润 = 活动后售价 RMB + 本场景规则收入 − 计算总成本 − 本场景规则成本

利润率 = 活动后利润 RMB ÷ 计算总成本 RMB（成本为 0 时显示空值，不显示无穷/异常）
```

引擎实现为独立双场景编排 `calculate_profit_scenario(price_usd, reserve_rate=0)` 与
`calculate_dual_profit(no_activity_price_usd, reserve_percent)`；每个场景按其真实售价作为规则条件上下文独立执行。旧接口 `calculate_profit()` / `sale_price_for_target_profit()` / `sale_price_for_target_rate()` 保持兼容，既有测试全部通过。

### 3.2 driver 状态

主输入状态 `profit_driver ∈ { profit_rate, no_activity_price, no_activity_profit, activity_profit }`。用户每次编辑的字段成为当前主输入；成本/汇率/规则变化时保留当前 driver 的目标值重算其余字段；尚无主输入时有有效无活动售价则以其为基准，否则只更新换算与空状态，不猜售价。防递归：`_profit_updating` + `QSignalBlocker`。

### 3.3 四个可编辑主字段的联动

| 编辑字段 | 联动行为 |
|---|---|
| 利润率 | 目标活动后利润 = 成本×利润率 → 反推最低有效活动后售价 → 按预留反推无活动售价 → 无活动利润 → 两规则状态 |
| 无活动售价 USD | 保持用户值 → 无活动利润 → 活动后售价 → 活动后利润 → 利润率 → 两规则状态 |
| 无活动利润 RMB | 反推最低有效无活动售价 → 活动后售价 → 活动后利润 → 利润率 → 两规则状态 |
| 活动后利润 RMB | **活动预留百分比保持不变** → 反推最低有效活动后售价 → 无活动售价 = 活动后售价÷(1−预留) → 无活动利润 → 利润率 → 两规则状态 |

反推使用现有分段/阈值搜索，返回达到目标利润的最低非负有效售价；两场景分别求解；不用界面四舍五入值污染内部计算，不用暴力细步长扫描。全部实时更新（valueChanged 级），无需点击"系统计算"。

### 3.4 活动预留修改行为

修改活动预留 % 时：无活动售价 USD 保持不变 → 活动后售价/利润/利润率随之改变 → 两场景规则重新独立判断。**不会**为保持原活动后利润而修改无活动售价，**不会**反推改写预留百分比。

### 3.5 两场景规则状态

`lblNoActivitySubsidyStatus` / `lblActivitySubsidyStatus` 紧凑显示：无规则 / 未触发 / 已触发 +$X.XX / 已调整 ±¥X.XX；多条命中只显示合计；tooltip 列出规则名称、判断场景、条件、收入/成本、原币金额、换算 RMB。两场景**分别独立判断**，不共用状态、不复制命中结果（含 29 USD 门槛跳变场景已测试）。新增非破坏性 `RuleEvaluation` 明细结构，原规则数据格式不变。

### 3.6 SHEIN 核价比较

核价 USD 可输入、RMB 冻结换算、可为空、不参与任何利润公式、不阻止保存。与无活动售价 USD 比较：核价为空不提醒；售价 ≤ 核价显示"未超过核价"；售价 > 核价红色提醒"超过核价 $X.XX"，差额与比例写入 tooltip，`lblProfitConclusion` 同步简要说明。

### 3.7 记录向后兼容

新记录附加 `profit_scenarios` 字段（`schema_version: 2.6.1-dual-profit-v1`），含 driver、计算总成本、核价、预留、两场景售价/利润/规则状态；旧字段保留不删除。旧记录打开时：旧售价映射为无活动售价，旧利润仅作兼容显示，不伪造双场景历史，缺失新字段安全为空；新记录保存后重新打开，利润字段、driver、规则状态与手动成本一致。AI 原始数据、包装候选、物流快照、反馈字段未动。编解码器：`application/profit_scenario_codec.py`。

### 5.4 已知问题
