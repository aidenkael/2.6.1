# UI_BASELINE

## 1. 基准地位

本目录中的两张图片是 `Profit-Accounting-2.6` 的最高视觉基准。它们用于锁定页面结构、信息层级、卡片关系、可编辑/只读区分和主要可见交互。

功能与业务逻辑以 `Development rules-2.6.md` 为准；当预览图中的示例数据、临时文字或版本号与总规冲突时，以已确认总规为准，并在 `UI_DEVIATION_REGISTER.md` 留痕。

## 3. 必须保持的视觉关系

- 左侧固定导航，右侧单页工作区；
- 浅色背景、白色卡片、蓝色主操作；
- 页面信息密度紧凑但不拥挤；
- 输入框、选择卡片、只读结果卡有明显层级差异；
- 新商品测算页按“图片输入 → AI摘要 → 成本规格/货代/系统成本 → 利润测算 → 底部操作”纵向排列；
- 设置页按“基础设置 → 货代管理 → 利润调整规则 → 页面操作”排列；
- 货代、包装档、规则列表使用可见选中态；
- 主要结果使用更明显的字号或底色；
- 不增加多余向导、模式切换或第三个底部主按钮。

## 4. 允许的自适应

以下变化不视为偏差：

- 根据 Windows 缩放和窗口宽度调整间距、字体或卡片伸缩；
- 在不改变信息层级的前提下使用滚动区域；
- 图标替换为 PySide6 可稳定实现的等义图标；
- 示例金额、用户名、目录、更新时间和版本号由真实数据替换；
- 为无障碍和可读性增加键盘焦点、错误提示和禁用态。

## 5. 必须登记的偏差

- 新增、删除、改名或合并控件；
- 改变区域顺序或把一页拆成多步向导；
- 改变可编辑/只读属性；
- 增加模式切换、第三个底部主按钮或复杂弹窗；
- 把全局尾程费改为货代表中可见的独立字段；
- 把归档变成硬删除；
- 向普通用户展示置信度、候选组、scope 或原始 JSON。

## 6. 验收方法

1. 使用相同或接近 1648 × 928 的窗口截图对比；
2. 按 `UI_FUNCTION_MATRIX.md` 逐项核对控件；
3. 检查可编辑、只读、选中、禁用、错误和未保存状态；
4. 检查 100%、125%、150% Windows 缩放下的可用性；
5. 所有偏差必须在 `UI_DEVIATION_REGISTER.md` 有已确认记录。
