# OUT_OF_SCOPE

## 1. 阶段 0 不做

- 不写业务代码；
- 不迁移源文件；
- 不修正 import；
- 不创建完整 PySide6 页面；
- 不运行迁移测试；
- 不生成迁移压缩包；
- 不修改旧利润软件；
- 不修改物流算法或校准数据；
- 不未经确认合并到默认分支 `main`。

## 2. 迁移基线任务不做

- 不实现完整新商品测算页功能；
- 不接真实视觉 API；
- 不实现完整历史页、导入导出页、校准页或以图搜图页；
- 不开发完整设置页业务；
- 不迁移真实旧数据库和用户图片；
- 不发布正式产品安装包；
- 不以迁移为由重构所有旧代码；
- 不把旧 Tkinter UI 自动翻译成 PySide6；
- 不开发物流版本打包器的完整生产能力；
- 不把 R2 之外的三份 AI JSON 加入基线。

## 3. 2.6 第一版产品不做

- 自动核价决策；
- 自动上架；
- ERP 同步；
- 多商品批量 AI 识图；
- 多 SKC 同时核算；
- 1688 完整网页采集；
- 浏览器批量采集与反爬体系；
- 云端后台与云同步；
- 登录、权限和多人协作；
- 自动训练模型；
- 软件自动修改 Python 代码；
- 通用插件市场；
- 在线自动更新服务器；
- 复杂全版本历史时间线；
- 复杂报表系统；
- 本地 OCR 作为正式主识别方案；
- 自动强制选择最低价货代；
- 把 AI 候选、置信度、scope、group_id 等技术字段暴露给普通用户。

## 4. 禁止的技术过度设计

- 微服务；
- 自研 ORM；
- 复杂依赖注入框架；
- 事件总线或工作流引擎；
- 为未来可能性预建无调用接口；
- 为“架构完整”增加空层、空仓储或空适配器；
- 在 2.6 内平行维护第二套物流核心算法；
- 把校准规则永久硬编码进 Python；
- 把可配置货代、汇率、尾程费或利润规则写死在 UI。

## 5. 旧项目明确排除

- Tkinter 主窗口、ProductPage、旧历史页：仅作参考；
- 旧 OCR 对话框与复杂候选表：不作为最终入口；
- `.venv`、缓存、测试临时目录、构建产物和旧压缩包；
- 真实数据库、真实用户图片、浏览器 Profile、Cookie、Token、API Key；
- `Image Search/` 在 R2 外的未提交修改；
- 无效阶段报告和已作废旧需求。

## 6. 进入范围的条件

任何本文件中的功能只有在用户明确提出、说明业务价值并完成以下流程后才可进入：

1. 更新 `Development rules-2.6.md`；
2. 如涉及 UI，登记 `UI_DEVIATION_REGISTER.md`；
3. 评估数据、利润、物流和历史兼容风险；
4. 用户确认；
5. 单独立项、测试和验收。
